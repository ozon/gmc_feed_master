## Overall assessment

The backend is well-structured and the core mechanical invariants are largely intact: migrations cover the hot FK columns, delta hashing is canonical and stable, export writes are atomic (`temp` → `os.replace`), and the per-feed-source lock does skip overlapping runs in the single-worker deployment it targets. The most serious problem is in the shared scope-enforcement dependency, which can be short-circuited by an attacker-supplied `client_id` query parameter, giving any non-admin user cross-tenant access. Secondary issues cluster around blocking work in the event loop (file I/O, XML rendering, synchronous plugins), per-row write amplification for large catalogs, and SSRF via user-controlled URLs.

## Findings

### Critical

**[B1] Cross-tenant authorization bypass in `enforce_scope_access`** — `app/access.py:87-104`. *(Controller-verified.)*
The guard resolves `client_id` first (`path_params` or `query_params`) and, when it matches one of the user's clients, returns at line 104 **before** the `feed_source_id` branch at lines 105-123 runs. Any non-admin with at least one assigned client can append `?client_id=<own_id>` to a `/feed-sources/{id}/...` route and skip the feed-source ownership check. All feed-source routers receive this guard only at the router level (`main.py:209-220`), and the inner `require_feed_source` (`app/access.py:149-158`) is an **existence check only** — it does not re-validate scope, so it does not mitigate. Confirmed route families affected: products, quality findings/history, export history, field mapping, pipeline, dry-run, dashboard, registry.
*Impact:* cross-tenant read of products, export history, QC findings, field mappings, plus run triggering. A scoped user can enumerate another client's feed sources.
*Recommendation:* evaluate **every** present scope identifier before returning — if both `client_id` and `feed_source_id` are present, validate both (and validate that `feed_source_id`'s `client_id` is in `user.client_ids`). Never short-circuit. Add cross-tenant authorization tests: **none exist today** for this function.
*Relation to prior review:* the 2026-09-08 `B1` covered the missing-param fallthrough to global tier; this is a distinct remaining bypass via a caller-supplied param in the same function. Both point at the same fix shape.

### High

**[B2] SSRF via user-controlled URLs** — `app/ingest/fetch.py:32`, `app/routes/clients.py:144-146`, `app/qc/image_probe.py:36-41`.
`source_url` and product image URLs are fetched with no scheme/host allowlist and no private/link-local IP blocking; the image probe also follows redirects. Any authenticated user can reach internal services or cloud metadata (`169.254.169.254`).
*Recommendation:* enforce `http`/`https` only, resolve and reject loopback/private/link-local ranges, and validate redirect targets (re-apply the check per hop).

**[B3] Export renders the whole feed in memory and does sync file I/O on the event loop** — `app/export/service.py:80,128,150`, `app/export/store.py:10,38`, `app/export/renderer.py:68-87`.
The renderer builds one in-memory byte string, then `async` functions call synchronous `write_bytes` / `read_bytes` / `os.replace`. On the single-worker deployment this stalls every request and the scheduler, and doubles peak memory for large catalogs. It also contradicts AGENTS.md's "streams output rather than building the full feed in memory above the threshold documented in `docs/architecture.md`".
*Recommendation:* stream XML to the temp file and run file operations via `asyncio.to_thread`; gate on the documented threshold.

### Medium

**[B4] Plugins run synchronously with no timeout** — `app/pipeline/steps.py:247-262`.
`plugin_obj.process(...)` is awaited directly, with no `asyncio.wait_for` and no executor. AGENTS.md explicitly requires "a per-plugin `asyncio.wait_for` timeout so a hanging plugin can't stall the per-feed-source lock". A blocking plugin freezes the whole event loop.
*Recommendation:* run sync plugins in a thread (`asyncio.to_thread`) or require async, wrapped in `asyncio.wait_for(timeout)`.

**[B5] Per-plugin run state is keyed by plugin name, so two instances collide** — `app/pipeline/steps.py:210-229,248`.
`run_states` / `accepts_state` are keyed by plugin name; two instances of the same plugin in one pipeline share and overwrite each other's `prepare_run` state.
*Recommendation:* key by `ModuleInstance` / position rather than manifest id.

**[B6] Per-row write amplification in staging, plugin outcomes, and retention** — `app/staging/persistence.py:86-107,172-192`, `app/staging/service.py:394-395`.
`apply_staging_delta` and `apply_plugin_outcomes` issue one `UPDATE` per product; `_prune_retention` deletes per row. Thousands of statements per run.
*Recommendation:* `executemany` / `insert(...).on_conflict_do_update` or a CASE-based bulk update inside the existing chunked transactions.

**[B7] Whole-catalog and whole-table loads per run/request** — `app/staging/persistence.py:28-42,198-208`, `app/staging/config_resolver.py:102-106`, `app/routes/products.py:279-283`.
`load_stored_rows` eagerly loads every stored product's JSONB `raw_data` although only hashes/status are used; `load_export_bound` and `lookup_products` load the entire catalog; `resolve_config_bundle` loads all `PluginConfig`/`PluginData` rows and filters in Python.
*Recommendation:* select only required columns; push plugin-config filtering into SQL; paginate/stream lookups.

**[B8] Image-dimension cache insert races under concurrency** — `app/qc/image_probe.py:66-73`, `app/models/image_dimension.py:12`.
Inserts rely on a unique URL constraint with no `ON CONFLICT`; two concurrent feed-source runs probing the same URL race to `IntegrityError`, which then recurses in `_cache_error`.
*Recommendation:* `insert(...).on_conflict_do_nothing()`.

### Low

- **[B9] `Image.open(BytesIO(body))` blocks the event loop** — `app/qc/image_probe.py:51`. Decode in a thread.
- **[B10] Engine built with pool defaults** — `app/db/engine.py:18-19`. No `pool_pre_ping`/`pool_size`/`max_overflow`; stale connections after a DB restart surface as opaque errors.
- **[B11] No login rate limiting; weak password policy** — `app/main.py:297-313`, `app/schemas/admin.py:33`, `app/auth.py:23`. New-password validation is `min_length=1`. Add throttle/backoff and a password policy.
- **[B12] No CORS middleware** — `app/main.py:208`. Fine if the frontend is always same-origin via proxy; document that explicitly or add an allowlist.
- **[B13] `/health` mutates global state per request** — `app/main.py:292-295`. The unauthenticated handler assigns `app.state.settings` on every call; drop the side effect.
- **[B14] Secrets stored plaintext (known, deferred)** — `app/models/ai.py:31` (AI provider `api_key`) and `FeedSource.configuration` (`basic_auth`). Documented MVP decision; flagged, not patched.

## Coverage gaps

- No test exercises `enforce_scope_access` — the Critical finding is untested.
- The lock tests simulate overlap by manually acquiring the lock rather than asserting a genuinely concurrent second run is skipped, which AGENTS.md requires.

## Top 5 priority actions

1. Fix `enforce_scope_access` to stop short-circuiting on `client_id`; add cross-tenant tests for every feed-source route family.
2. Harden outbound fetches (ingest + image probe): scheme allowlist, block private/link-local IPs, control redirects.
3. Move export rendering and file I/O off the event loop (streaming + executor).
4. Replace per-row staging/plugin/retention writes with bulk operations.
5. Give plugins a threaded/async execution path with a hard timeout, and fix per-instance run-state keying.

## Verified invariants (held up)

Atomic publish (`temp` → `os.replace`), per-feed-source lock semantics under single-worker, delta/content-hash canonicity, reserved-route contract enforcement, migration chain linearity, export-token redaction, and clean `ruff`/`mypy` gates.
