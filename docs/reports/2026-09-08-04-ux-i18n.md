# UX & i18n Review — 2026-09-08

Scope: user-facing behavior of `frontend/src/**` (rendered structure, interaction handlers), all locale files `frontend/public/locales/{en,de}/*.json`, copy quality, accessibility, navigation.
Method: page-by-page JSX reading + namespace-by-namespace en/de diff; German copy reviewed for grammar and register. Read-only review. Findings cross-corroborated where two agents independently reported them (U2=F3, U3/U4=F7, U13=F11, U1≈F10).

Severity legend: Critical · Important · Medium · Minor.

## Findings

### [U1] Token-rotation failure can present as success
- Severity: **Important** (security-relevant feedback; see nuance)
- Location: `frontend/src/components/ExportUrlBlock.tsx:32-38`; no `rotateFailed` key exists in either locale tree
- Evidence: `onError` passes `t('rotated')` — the success string "Export token rotated successfully" / "Export-Token erfolgreich rotiert" — as the fallback to `notifyMutationError`. Nuance (controller-verified): when the server returns an `ApiError` with `detail`, the real (English) detail is shown instead; the misleading success text appears exactly when there is no detail — network failure, 5xx without body.
- Impact: on failure the operator may believe the old export URL is dead and stop treating it as live — while the old token still works. This is the only destructive security-relevant action in the app whose failure can read as success.
- Suggestion: add `export.rotateFailed` (en+de) and use it as the error fallback; collapse the identical if/else branches.
- Status: NEW (controller-verified)

### [U2] Labelizer saves fail silently
- Duplicate of frontend F3 (`CustomLabelsUI.tsx:237-252`): no try/catch around `mutateAsync`, no toast on failure, unhandled rejection. Important — see frontend report for details.

### [U3] de/notifications.json missing 3 auto-mapper keys
- Severity: **Important**
- Location: `frontend/public/locales/de/notifications.json` vs en (8 vs 5 keys)
- Evidence: en has `autoMappingRunning` ("Running auto mapper…"), `autoMappingDone`, `autoMappingFailed`; de has none of the three.
- Impact: German users get raw keys/English in the mapping tab's most visible feedback loop.
- Suggestion: `"autoMappingRunning": "Automatische Zuordnung läuft…"`, `"autoMappingDone": "Automatische Zuordnung abgeschlossen"`, `"autoMappingFailed": "Automatische Zuordnung fehlgeschlagen"`.
- Status: NEW

### [U4] de/export.json missing `compareVersions`
- Severity: **Important**
- Location: `frontend/public/locales/de/export.json`; key used at `ExportPage.tsx:89` — the primary compare action button
- Suggestion: `"compareVersions": "Versionen vergleichen"`.
- Status: NEW

### [U5] Product table rows are click-only — no keyboard path to details
- Severity: **Important**
- Location: `frontend/src/features/products/ProductsTable.tsx:156-161`
- Evidence: `<Table.Tr onClick={...} style={{ cursor: 'pointer' }}>` — no `tabIndex`, no `role`, no key handler; `highlightOnHover` is the only affordance.
- Impact: keyboard and screen-reader users cannot open the product details drawer at all; touch users get no visible affordance until first tap.
- Suggestion: `tabIndex={0}` + `role="button"` + Enter/Space handling, or an explicit "details" control in the first cell; aria-label naming the product.
- Status: NEW

### [U6] Raw English enum values rendered as content
- Severity: **Important**
- Location: `FindingsTable.tsx:34` (`{finding.severity}`), `IngestionRunsTable.tsx:37` (`{status}`), `ProductsTable.tsx:185` (status badge), `MonitoringFindingsPage.tsx:31` (severity MultiSelect options)
- Evidence: badges literally render `critical`, `running`, `removed`, `skipped` while sibling columns use `t()` — and translations already exist (`dashboard.runStatus.*`, `products.stateRemoved`, …).
- Impact: in the German UI, core data columns stay English; inconsistent with the translated headers on the same tables.
- Suggestion: map through existing keys with safe fallback (`t(\`runStatus.${status}\`)` pattern); localize the severity filter options.
- Status: NEW

### [U7] German register clash: customLabels uses "du", the rest of the app uses "Sie"
- Severity: **Important**
- Location: `frontend/public/locales/de/customLabels.json` (idsUnavailable, unsavedChanges, deleteConfirmBody, valueTemplateHint, …)
- Evidence: "Öffne dieses Plugin über einen Client…", "Du hast ungespeicherte Änderungen…" vs de/dashboard "Geben Sie {{name}} ein…" and de/pipeline "Wählen Sie ein Plugin…".
- Impact: an operator-facing B2B tool abruptly switches to informal address on the most recently built page — reads as unreviewed copy.
- Suggestion: normalize customLabels de copy to Sie-form; add a review step for German copy in the i18n workflow.
- Status: NEW

### [U8] German grammar errors in rule-delete confirmations
- Severity: Medium
- Location: de/customLabels.json `deleteConfirmBody`, `deleteGlobalWarning`
- Evidence: "Regel \"{{name}}\" löschen? Bis zum Speichern kannst du es mit Abbrechen zurücknehmen." — "es" mis-refers to feminine "Regel"; "mit Abbrechen zurücknehmen" is unidiomatic.
- Suggestion: e.g. "Regel \"{{name}}\" löschen? Sie lässt sich bis zum Speichern über Abbrechen wiederherstellen."
- Status: NEW

### [U9] Denglisch / mistranslations in de customLabels
- Severity: Medium
- Location: de/customLabels.json (`matchMode.all` "Alle Produkte treffen", `coverage.labeledOf` / `noStagedProducts` "gestagte Produkte" — "gestagt" is not a German word), `common` `scope.feed_sourceHint` "Gilt für diese Feed-Source"
- Impact: reads as machine-translated jargon; erodes trust in the German UI.
- Suggestion: "Alle Produkte zuordnen"; "vorgemerkte Produkte" or "Produkte im Staging"; unify on "Feedquelle".
- Status: NEW

### [U10] Terminology inconsistency: "Mandant" vs "Kunde" for client
- Severity: Medium
- Location: de/dashboard.json ("stats.clients": "Mandanten" but "manageClients": "Kunden verwalten") vs de/admin.json / de/common.json ("Kunden")
- Impact: the same entity has two names across (and within) pages; users cannot be sure Dashboard clients and Admin clients are the same thing.
- Suggestion: pick one term (recommend "Mandant" given breadcrumbs/stats) and sweep all namespaces.
- Status: NEW

## UX health verdict

The interaction foundation is strong: every data view has Loading/Empty/Error states, destructive flows use type-to-confirm modals, and the dirty guard exists on all editor pages. The gaps cluster in three places: **failure feedback** (U1, U2, plus the frontend error-path cluster), **German copy quality** (register clash, Denglisch, grammar, missing keys — the labelizer cycle moved fast and skipped German review), and **untranslated data values** (U6) plus **keyboard access on the products table** (U5). One focused i18n pass (missing keys + plurals + register) would resolve roughly half the findings by count.
