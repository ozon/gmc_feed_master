# Frontend Review — 2026-09-17

Scope: `frontend/` — `src/` (api, app, components, features, i18n, test, types), `package.json`, `vite.config.ts`, `tsconfig*.json`, `docs/`. Read-only; no code modified.

Command results at review time:
- `npm run typecheck` (`tsc -b`) → passed, no output
- `npx vitest run` → 100 files / 564 tests passed (~144s; only Node `localStorage` experimental warnings)

## Overall assessment

The frontend is in good shape: `tsc -b` is clean under `strict`, there is zero `any`/`as any` in production code, i18n keys are fully typed from the `en` locale JSON and `de` has 100% key parity, all routes are lazy with vendor chunk grouping, tests are behavior-level with realistic fetch stubs, and ADR-0004 plugin error isolation is correctly wired in both plugin surfaces. Server-state discipline is mostly respected — the deviations are drafts/accumulators, and only two are true ADR-0001 violations. The main weaknesses are one real form-dirty bug, missing lint tooling, and a few memoization/performance rough edges on hot list pages.

## Findings

### High

**[F1] Feed settings cannot be saved when only AI-QC or basic-auth fields change** — `src/features/setup/FeedSettingsForm.tsx:261-269`. *(Controller-verified.)*
Save is gated on TanStack Form `isDirty` (`selector={(state) => ({ isDirty: state.isDirty })}`, `disabled={!isDirty}`), but the AI-QC switch/budget and Basic-Auth username/password live in separate `useState` (lines 35-45) and never affect `isDirty`. Changing only those fields leaves Save disabled, so the user cannot persist them. The tests hide this by editing `name` first (`FeedSettingsForm.test.tsx:88,108,182`).
*Recommendation:* move those fields into the form, or compute `disabled={!isDirty && !configDirty}`. Add a regression test that edits only the switch.

### Medium

**[F2] Taxonomy search bypasses TanStack Query and swallows errors** — `src/features/category/TaxonomyCombobox.tsx:24-35`.
Hand-rolled `useEffect` + `apiGet` + local `entries`, no Query cache/dedupe, and errors collapse to `{items: []}` (line 35), making failures indistinguishable from "no results". Violates ADR-0001.
*Recommendation:* `useQuery` keyed on `(language, debouncedQuery)`.

**[F3] Findings list re-filters and re-groups on every keystroke** — `src/features/monitoring/findings/FindingsExplorer.tsx:118`.
`codes`, `filtered`, and `groups` run unmemoized on every render.
*Recommendation:* `useMemo` keyed on `findings`/`severities`/`rules`/`search`.

**[F4] Paged server data accumulated into local state** — `src/features/category/MatchesModal.tsx:33`.
`items`/`total` are accumulated via `useEffect`; with Query's default `refetchOnWindowFocus`, a focus refetch at `offset > 0` re-merges into the accumulated list.
*Recommendation:* `useInfiniteQuery` (or disable refetch for this query) instead of manual accumulation.

**[F5] No frontend lint tooling** — `package.json:9`. *(Duplicate of `T3`.)*
No ESLint/Prettier/Biome config or `lint` script exists anywhere in `frontend/`; only `tsc` runs, so `react-hooks/exhaustive-deps` violations go unnoticed (e.g. `ProductsPage.tsx:104` omits `updateParams`). See `04-tooling-testing.md` `T3` for the fix.

**[F6] Dirty drafts have no navigation guard** — `src/features/setup/MappingTab.tsx:45`.
`MappingTab` and `FeedSettingsForm` hold dirty local drafts but have no `useBlocker`, unlike rules/filter/labelizer/pipeline (`rg useBlocker` finds only 5 files). Navigating away silently discards mapping edits.
*Recommendation:* add the same `ConfirmModal` guard pattern.

**[F7] Product page memo chain is defeated** — `src/features/products/ProductsPage.tsx:66`.
`allFields` is rebuilt every render, so `mergedFields` (line 68) and the `useProductColumns` inputs change identity each render and recompute the full column list.
*Recommendation:* memoize `allFields` on `fieldsQuery.data` and `dataFields` on `query.data?.fields`.

### Low

- **[F8] Hardcoded strings in the prompt-diff modal** — `src/features/admin/promptLibrary/PromptLibraryPage.tsx:207,209,214,216` ("System"/"User") while every sibling string is translated. Add `promptLibrary.diff.system/user` keys; en/de parity is otherwise complete.
- **[F9] Stale confirmation text can pre-arm a destructive action** — `src/components/ConfirmModal.tsx:29`. `confirmText` is never reset on close. Reset it in an `opened === false` effect or `onClose`.
- **[F10] Dead/no-op code** — `src/features/placeholders.tsx` (0-byte file) and `src/features/products/ProductDrawer.tsx:19` (`{productId === null && null}`). Delete. (Also tracked in `05-overengineering-audit.md` `O12`.)
- **[F11] Hand-written API types can drift from backend schemas** — `src/api/types.ts:1`. No OpenAPI codegen or contract test. Low today (types are detailed and strict); consider generated types or a schema-snapshot test.
- **[F12] Duplicate error-parsing implementation** — `src/features/setup/MappingTab.tsx:17` re-implements `mapFieldErrors` (`notifyApiError.ts:5`) with a different offset (`slice(idx+2)` vs `+1`+trim), so the two parsers can disagree. Reuse the shared helper.
- **[F13] Index keys on reorderable lists** — `src/components/JsonSchemaForm.tsx:66`, `FilterUI.tsx:169`, `RuleEditor.tsx:175`. Index keys can mis-associate row state when a middle row is deleted. Use a stable id per row.
