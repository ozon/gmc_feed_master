Scope: Makefile, docker-compose.yml, Caddyfile(.dev), `.github/workflows/ci.yml`, backend pyproject/uv.lock/alembic, frontend package.json/vite.config/tsconfig/vitest, gitignore/hygiene, AGENTS/README command accuracy.

Severity legend: Critical · Important · Medium · Minor.

## Findings

### [T1] CI runs no backend lint and no typecheck — the documented gates are fiction in CI
- Severity: **Important** (rated Critical by the reviewing agent because AGENTS.md/`make check` advertise a "full CI check"; downgraded by the controller — quality-gate debt, not a production-breakage class)
- Location: `.github/workflows/ci.yml:35-37`
- Evidence: backend job = registry check → `uv run alembic upgrade head` → `uv run pytest -q && uv run python -m compileall app alembic registry`. No `ruff check`, no `mypy`, anywhere in ci.yml. Frontend job = tests + typecheck + build (no lint — none exists, T7).
- Impact: AGENTS.md, `make backend-check`, and `make check` promise lint+typecheck as gates; CI enforces neither. The ruff "zero new errors in touched files" convention and the mypy 42-error baseline (TODO 10.1) regress silently.
- Suggestion: add CI steps for `uv run ruff check .` (after T2 makes it installable) and the mypy baseline gate; add a frontend lint gate after T7.
- Status: NEW (baseline numbers themselves are CONFIRMED-known)

### [T2] ruff is not declared in the backend dev group — `uv run ruff` only works via a global install
- Severity: **Important**
- Location: `backend/pyproject.toml:18-26` (dev group), `backend/uv.lock` (no ruff entry)
- Evidence: dev group lists alembic, mypy, pytest*, pytest-postgresql, pytest-xdist — no ruff. `uv run ruff` (AGENTS.md, Makefile:52,56) succeeds today only because ruff happens to be on the machine's PATH; a fresh clone or CI container fails with command-not-found.
- Impact: documented commands break on clean environments; CI cannot add the ruff gate (T1) until this is fixed; version is unpinned so results vary by machine.
- Suggestion: add a pinned `ruff` to the dev group and re-lock (mirrors the mypy 2.3.1 pattern from 2026-09-08).
- Status: CONFIRMED-known-worse (msg board said "unpinned but installed"; it is actually absent from the lockfile)

### [T3] Alembic ignores `DATABASE_URL` — README/AGENTS migration commands are misleading
- Severity: **Important**
- Location: `backend/alembic/env.py:10,17,29` (only `config.get_main_option("sqlalchemy.url")`); `backend/alembic.ini:4` (hardcoded `postgresql+asyncpg://postgres:postgres@localhost:5432/gmc_feed`)
- Evidence: env.py never reads `os.environ` or `Settings().database_url`; root AGENTS.md, backend/AGENTS.md, and README instruct `DATABASE_URL=… uv run alembic upgrade head`, but that variable has no effect on Alembic. `.env.example` ("Runtime and Alembic migration URL") is wrong for the Alembic half.
- Impact: on any host whose Postgres is not the hardcoded localhost URL, migrations silently target the wrong database (or fail). CI passes only because the hardcoded URL happens to match the CI service.
- Suggestion: in env.py, override `sqlalchemy.url` from `DATABASE_URL`/Settings when set (conftest already uses the `set_main_option` pattern).
- Status: NEW

### [T4] `make plugin-test` (and therefore `make test`) cannot work as written
- Severity: **Important**
- Location: `Makefile:108`, consequential `Makefile:150`
- Evidence: `uv run pytest backend/tests/test_plugin_contract.py` runs from the repo root; `uv run` searches **upward** for a pyproject and the repo root has none — and even from `backend/` the path would need to be `tests/test_plugin_contract.py`.
- Impact: the AGENTS.md "Always run contract tests" workflow is broken via Make; `make test` includes the target and fails at that step.
- Suggestion: `cd $(BACKEND_DIR) && uv run pytest tests/test_plugin_contract.py`.
- Status: NEW

### [T5] backend/AGENTS.md setup command references a nonexistent file
- Severity: Medium
- Location: `backend/AGENTS.md` "From backend/: `cp .env.example .env`"
- Evidence: `backend/.env.example` does not exist; the file lives at the repo root and `app/config.py` loads `parents[2] / ".env"` (root `.env`).
- Impact: copying from `backend/` fails; a user who creates `backend/.env` gets it silently ignored.
- Suggestion: `cp ../.env.example ../.env` (or point at the root instruction).
- Status: NEW

### [T6] Caddyfile ships a placeholder document root
- Severity: Medium
- Location: `Caddyfile:31` — `root * /path/to/frontend/dist`
- Impact: `make prod` serves 404s for all static assets until an operator hand-edits the Caddyfile; nothing parameterizes it.
- Suggestion: `root * {$FRONTEND_DIST:/srv/gmc/frontend/dist}` or a README callout for the required edit.
- Status: NEW

### [T7] No frontend linter exists at all
- Severity: Medium
- Location: `frontend/` — no eslint/prettier/biome config; `npm run lint` does not exist; `make lint` silently omits the frontend
- Evidence: only `tsc -b` runs via typecheck/build. React-hooks rules violations (see frontend F1) are exactly the class a linter would catch.
- Suggestion: add eslint (+ typescript-eslint, react-hooks, jsx-a11y) and a `lint` script; wire into `make lint` and CI.
- Status: NEW

### [T8/T10] Chunking option concern — REFUTED
- Severity: — (refuted on verification)

- Verification: current Vite 8 documentation confirms `build.rolldownOptions.output.codeSplitting.groups` is the **correct, documented** Vite 8 API replacing the removed `manualChunks` (official playground example uses exactly this shape; migration guide names `codeSplitting` as the replacement). `frontend/vite.config.ts:22-32` is valid as written.
- Status: REFUTED (kept on record to prevent re-reporting; related D9/D10 doc-drift findings about Vite/Rolldown in docs remain valid)

### [T11] docker-compose postgres has no restart policy

### [T12] Caddy: no compression, no security headers, default admin listener
- Severity: Minor
- Location: `Caddyfile` (whole file)

- Suggestion: add `encode gzip`, basic security headers; consider `admin off` in prod.
- Status: NEW

### [T13] No `engines` field in frontend/package.json; `.nvmrc` is gitignored

- Location: `frontend/package.json` (no engines), `.github/workflows/ci.yml:48` (node 22), `.gitignore:56` (`.nvmrc` ignored)
