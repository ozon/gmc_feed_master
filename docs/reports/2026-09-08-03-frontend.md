# Frontend Code Review — 2026-09-08

Scope: `frontend/src/**` (api, app, components, features, i18n, test, types) plus build-relevant config. Code-level correctness only; UX/i18n content issues live in the UX report, tooling in the tooling report.
Method: CodeGraph-assisted flow tracing + targeted reads; controller re-verified the Important findings (F1, F2, F3) directly in source. Read-only review.

Severity legend: Critical · Important · Medium · Minor.

## Findings

### [F1] Conditional hook call in SetupPage (Rules of Hooks violation)
- Severity: **Important**
- Location: `frontend/src/features/setup/SetupPage.tsx:17-21`
- Evidence: `if (!feedSourceId) { return <ErrorState ... />; }` (line 17-19) executes **before** `const feedSource = useFeedSource(feedSourceId)` (line 21).
- Impact: if the component stays mounted while `feedSourceId` toggles between present and absent (route-shape changes, layout remounting), React throws "Rendered fewer hooks than expected" and the tree crashes. Even if the param is always present today, the pattern is statically wrong and would be flagged by react-hooks lint (which does not exist — see tooling T7).
- Suggestion: hoist `useFeedSource` above the early return and gate with `enabled: Boolean(feedSourceId)` (the hook already handles empty ids elsewhere).
- Status: NEW (controller-verified)

### [F2] Disabled export-diff query renders a perpetual loading spinner instead of the empty state
- Severity: **Important**
- Location: `frontend/src/features/export/ExportPage.tsx:38,92-97` + `frontend/src/features/export/ExportVersionDiff.tsx:15-17`
- Evidence: `useExportVersionDiff` receives `undefined` versions until Compare is pressed, so the query is `enabled: false` — TanStack Query v5 reports `status: 'pending'` for disabled queries. `ExportVersionDiff` checks `if (isPending) return <LoadingState />` **before** `if (!diff) return <EmptyState ... selectVersions ...>`, so the empty state is unreachable.
- Impact: on the Export page, users see a permanent spinner in the diff area until they select two versions and press Compare — reads as a hung request. The `selectVersions` hint i18n key (and its test value) never shows.
- Suggestion: branch on data first: `if (!diff && !isFetching) return <EmptyState .../>` (or pass `fetchStatus` and gate the spinner on `isPending && isFetching`).
- Status: NEW (controller-verified)

### [F3] CustomLabelsUI saves have no error handling — unhandled rejections, silent failure
- Severity: **Important**
- Location: `frontend/src/features/customLabels/CustomLabelsUI.tsx:237-252`; call sites `:295` (`void saveIds()`) and `:369` (`void saveRules()`)
- Evidence: `await saveConfig.mutateAsync({ slotRules: payloadRules })` / `await saveData.mutateAsync({ slotIds: effectiveIds })` with no try/catch, invoked via `void save…()`. A failed save (422/409/network) becomes an unhandled promise rejection; no toast fires; the dirty state persists silently.
- Impact: user edits stay on screen with zero feedback — the Labelizer appears to save when it hasn't (or appears to do nothing on validation errors). Every sibling page (PipelinePage, RulesUI, FilterUI, MappingTab) wraps saves in try/catch + `notifyApiError`; this is the outlier.
- Suggestion: wrap both in try/catch with `notifyApiError(error, t('saveFailed'))` (new key, en+de) matching the established pattern; add tests for the failure path.
- Status: NEW (controller-verified; duplicate of UX U2 — counted once)

### [F4] Possible null dereference on `user.client_ids`
- Severity: Medium
- Location: `frontend/src/features/admin/AdminUsersPage.tsx:85,150`
- Evidence: `{user.client_ids.length}` and `user.client_ids.map(String)`; the session `User` type in `frontend/src/api/client.ts:1` is `client_ids: number[] | null`.
- Impact: runtime TypeError (broken table) for any user whose API payload has `client_ids: null` (the backend returns null for unrestricted users).
- Suggestion: `user.client_ids?.length ?? 0` / `?? []`; align the `AdminUser` type with `number[] | null`.
- Status: NEW

### [F6] ProductsPage state not reset when the feed source changes

### [F8] FeedSettingsForm numeric fields accept NaN / out-of-range with no validation
- Severity: Medium
- Location: `frontend/src/features/setup/FeedSettingsForm.tsx:205-227`
- Evidence: `TextInput type="number"` with `onChange={(e) => field.handleChange(Number(e.currentTarget.value))}` and no TanStack Form validators. Clearing the field sends `0` (below `min={1}` for retention); partial input `1e` yields `NaN` which serializes as `null` in the payload.

- Suggestion: use Mantine `NumberInput` (already used in AdminSettingsPage) or add validators rejecting `NaN`/out-of-range before submit.

## Verified invariants (checked and hold)

- **Rollback invalidation** correctly prefix-matches `['feed-source', id, 'export-diff']` (hooks.ts:456-466).
- **401 handling**: `request()` exempts `/auth/login` + `/auth/password`; router handler removes the session query and preserves `pathname + search` in `state.from`; LoginPage restores it.
- **dnd-kit id stability**: `toLocal` mints collision-safe position-based ids (bump-past-held suffix loop); `toServer` strips and normalizes positions.
- **Pipeline save/reset cycle**: `setHydrated(false)` after save re-hydrates from the refetched server doc; failed instance PATCH rolls back + re-invalidates.
- **Session lifecycle**: `staleTime: Infinity` + `removeQueries` on logout + `resetQueries` after password change; `RequireAdmin` nested inside `RequireSession`.
- **Dirty-guard coverage**: `useBlocker` in PipelinePage, CustomLabelsUI, RulesUI, FilterUI (though both guards use native `window.confirm` — see UX U16).
- **useProductLookup**: normalized sorted cache keys, 30s staleTime, `keepPreviousData`, `enabled` requires feedSourceId + non-empty values.
- **MappingTab**: full-replace PUT semantics; 422 row errors parsed per source field.
- **PluginPage**: custom-component path suppresses URL-scope config fetch for asymmetric-scope plugins.
- **api client**: `parseError` tolerates non-JSON bodies; 204/empty handled; content-type mismatch raises `ApiError`.
- **State coverage**: all main data views implement Loading/Empty/ErrorState; `RouteErrorBoundary` distinguishes chunk-load failures (reload offered).
- **Known-confirmed**: ProductsPage parallel-load flake (documented), test double-wrap (TODO 6.2), `notifications.ts ↔ notifyApiError.ts` benign module cycle, PluginIconMap skeleton by design (TODO 3.5).

## Frontend health verdict

The state layer is disciplined — TanStack Query conventions are followed, invalidation is thorough, guards exist on the risky flows. The consistent weakness is **error-path handling on secondary surfaces**: the newest pages (labelizer, admin) and secondary actions (rotate, delete toasts, settings toggles) skipped the error-feedback pattern the older pages established. F1–F3 are small, high-value fixes.
